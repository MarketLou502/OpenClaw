# 2026-08-03

- Added an event-driven Apple Mail rule handler for Capital One messages.
  Matching mail is passed directly to the existing debit-only transaction
  parser, which updates dollars spent today/review state and pushes the
  dashboard. The 15-minute poll remains as reconciliation fallback.
- This does not alter Plaid balance sync or the Budget tab data source.
- Fixed cross-path duplication: the Mail rule and fallback poll serialized the
  same MIME source differently, so raw-source hashes diverged. Transaction
  identity now uses the stable email `Message-ID`; duplicate transaction rows
  192 (ChatGPT) and 195 (McDonald's) were removed.
- Replaced twice-daily paid `/accounts/balance/get` polling with incremental
  `/transactions/sync`. Plaid transaction changes now live in
  `plaid_transactions`, and cached balances returned by sync continue feeding
  `account_balances` and the Budget tab. The old implementation is archived at
  `archive/paid-balance-polling-2026-08-03/`. No active code calls the paid
  Balance endpoint or forced Transactions Refresh.
- Activated a signed Plaid webhook receiver through Tailscale Funnel. Capital
  One, Park Community Credit Union, and Venmo each delivered a verified
  `WEBHOOK_UPDATE_ACKNOWLEDGED` event. `SYNC_UPDATES_AVAILABLE` now triggers an
  Item-specific sync; the scheduled retrieval is reduced to one 03:15 daily
  reconciliation run.
